# MatchEdge — Transparent Football 1X2 Research

A production-style, mobile-responsive, static website for publishing **research-only** 1X2 predictions and keeping an honest, auditable results archive.

## What's included

- Home page, full archive with client-side search, individual prediction pages, methodology, about, privacy and custom 404.
- Semantic HTML, no client-side render dependency, SEO-friendly descriptions and social metadata.
- `robots.txt`, security headers, and **conditional** `sitemap.xml` and canonical links once the *real* public domain/subdomain is known.
- One authentic research record, now settled as PSG 2–2 Roma (loss). No fabricated win rates or ROI.
- A build script using only Node built-ins (no `npm install` necessary).

## Start locally

Prerequisite: Node.js >= 18. No Python, npm install or external server package required.

```bash
npm run build
npm run preview
```

Open http://localhost:4173

Alternatively, open `dist/index.html` directly, but use the preview server for internal links and paths.

## Configure name and canonical address

Edit `site.config.json`: `brand`, `description`, and `siteUrl`.

Do **not** set a guessed `pages.dev` address. After the deployment gives you a real URL, run:

```bash
SITE_URL=https://your-real-project.pages.dev npm run build
```

This creates canonical links, `sitemap.xml`, and a sitemap reference in `robots.txt`. You must redeploy the rebuilt version after this change.

## Update public predictions

Store all raw records in your **private** SQLite database. Keep private files outside the GitHub repository. Export just the public fields:

```bash
python3 scripts/import_sqlite.py /secure/path/to/football_1x2_tracker.sqlite
npm run build
```

The public JSON contains prediction timestamps, odds, EV, selection and the eventual result. **Do not revise existing prediction details after kickoff**; update only the result, status, and net units, with an audit note.

Match-specific editorial copy lives separately in `data/analyses.json` keyed by prediction `id`. This means re-importing your SQLite log will **not** overwrite the researched analysis. Cite reliable sources and keep any after-kickoff edits explicitly marked as retrospective.

## Deploy for free to Cloudflare Pages

1. Test locally, then create a GitHub repository with the source folder **excluding private SQLite files**. `dist/` can be committed (or generated by the build).
2. Cloudflare dashboard → **Workers & Pages** → **Create application** → **Pages** → **Connect to Git** → choose repo.
3. Build command: `npm run build`. Output directory: `dist`.
4. After Cloudflare assigns the real `.pages.dev` hostname, set the `SITE_URL` environment variable in Pages build settings to that exact HTTPS URL, and redeploy. This enables correct sitemap and canonical URLs.
5. Submit `https://...pages.dev/sitemap.xml` to Google Search Console. Indexing is not guaranteed.

Official deployment guide: https://developers.cloudflare.com/pages/framework-guides/deploy-an-astro-site/ (Astro) or https://developers.cloudflare.com/pages/framework-guides/deploy-anything/ (static).

## Integrity rules

- 1X2 only. Baseline range 52–70% win probability, 1.50 < odds <= 3.00, theoretical EV >= 3%, context checks.
- Borderline prices outside baseline filters must be recorded separately from strict-rule model passes. Visitor-facing match analysis should explain the football case and caveats rather than internal authorization workflows.
- Zero selections on any day is valid.
- No real-money stakes, no affiliate links, no guaranteed results or invented performance stats.

## Architecture

`data/predictions.json` + `data/analyses.json` -> `scripts/build.mjs` -> `dist/` static HTML, CSS and JavaScript. The brand is provisional and can be changed in the config and wordmark.

For a more advanced dynamic site later, the same data can be ported into Astro. This prototype deliberately avoids external dependencies to keep launch free and frictionless.
